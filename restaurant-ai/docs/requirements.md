# Requirements

## 1. Project Goal

餐廳每月需要進行食材庫存盤點，過程需要整理食材進貨、出餐及庫存異動資料，若依賴人工計算，不僅耗費時間，也需要熟悉餐廳庫存計算方式。

因此，本專案希望建立一套餐廳庫存管理系統，將食材、餐點與食材使用比例建立關聯，並透過進貨（IN）與出餐扣料（OUT）紀錄計算目前庫存，降低人工盤點與計算的負擔。

系統進一步設定各食材的最低庫存量，根據歷史使用量計算平均每日使用量、預測需求量及建議補貨量，協助使用者判斷後續所需的補貨數量，降低新人因不熟悉庫存計算方式而產生錯誤的情況。

原先規劃使用 AI 分析歷史資料並進行庫存預測，但實作後將庫存預測與補貨計算改由後端程式依照明確的 Business Rules 執行，以確保計算結果具有一致性與可預期性。

AI 則應用於「AI 庫存助理」，讓使用者可以透過自然語言詢問目前庫存、低庫存食材、庫存預測及補貨資訊，AI 再透過後端 Tools 取得實際資料後產生回覆。

## 2. User Roles

本系統主要使用者為餐廳內部人員，依照工作職責與資料管理需求分為 Admin 與 User 兩種角色。

### 2.1 Admin（主管級）

Admin 具備完整的庫存與餐點管理權限，可執行以下功能：

- 查看目前庫存
- 庫存管理
  - 新增、修改、刪除食材
  - Excel 匯入
  - 記錄進貨與出貨
- 查看歷史庫存記錄
- 使用庫存預測功能
- 餐點管理
  - 出餐
  - 新增餐點
  - 修改餐點
  - 刪除餐點
  - 查看餐點及食材比例
- 使用 AI 庫存助理

### 2.2 User（一般員工）

User 主要負責日常庫存查詢與餐點操作，具備以下功能：

- 查看目前庫存
- 查看庫存預測
- 餐點操作
  - 出餐
  - 查看餐點及食材比例
- 使用 AI 庫存助理

User 不具備以下管理權限：

- 新增、修改或刪除食材
- Excel 匯入
- 查看歷史庫存記錄
- 新增、修改或刪除餐點

## 3. Features

本系統提供餐廳庫存管理、餐點管理、庫存預測及 AI 輔助查詢等功能，主要功能模組如下。

### 3.1 Authentication & Authorization

提供使用者登入與角色權限管理功能。

- 使用者登入
- JWT 身份驗證
- Admin / User 角色區分
- 根據角色限制功能存取

### 3.2 Inventory Management

提供餐廳食材資料與庫存資訊管理功能。

- 查看食材清單
- 新增、修改食材、刪除食材
- 設定食材單位
- 設定食材單位成本
- 設定最低庫存量
- 查看目前庫存
- Excel 匯入

### 3.3 Stock Management

提供食材進出貨及庫存異動管理功能。

- 記錄進貨（IN）、出庫（OUT）
- 記錄庫存異動日期
- 根據庫存異動紀錄計算目前庫存
- 查看庫存異動資料

### 3.4 Meal Management

提供餐點及食材使用比例管理功能。

- 查看餐點
- 新增、修改、刪除餐點
- 查看餐點所需食材
- 設定餐點與食材的使用比例
- 執行出餐
- 出餐時依餐點食材比例扣除庫存

### 3.5 Dashboard

提供餐廳目前庫存狀況的視覺化資訊。

- 顯示食材總數
- 顯示目前庫存狀況
- 顯示進貨與出貨統計
- 顯示低庫存食材數量
- 顯示食材庫存圖表

### 3.6 Inventory Forecast

根據歷史庫存使用資料提供未來需求與補貨資訊。

- 設定歷史使用量計算期間
- 設定未來預測期間
- 計算平均每日使用量
- 計算預測需求量
- 計算建議補貨量
- 計算預估補貨成本
- 篩選需要補貨的食材
- 依補貨需求排序

### 3.7 History

提供管理員查詢歷史庫存及匯入記錄的功能。

- 查看歷史庫存異動
- 查看 Excel 匯入記錄
- 查看匯入成功與失敗筆數
- 查看匯入時間及結果

### 3.8 AI Inventory Assistant

提供自然語言的庫存查詢與資訊整理功能。

- 透過自然語言詢問庫存資訊
- 查詢低庫存食材
- 查詢庫存摘要
- 查詢庫存預測
- 依使用者問題選擇適合的 Inventory Tool
- 根據 Tool 回傳資料產生自然語言回答
